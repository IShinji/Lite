# 可选 MCP 长期授权

本文说明 MCP OAuth 长期授权模式的设计、配置与安全边界。默认行为不变：授权在管理员选择的时长后到期。新安装的最长时长仍是 24 小时，可以调高到 72 小时。

## 为什么需要

默认授权在 30 分钟到站点最长时长后失效，且 Lite 重启、授权时使用的浏览器登录会话被清理或被取代后，授权会一并失效。新安装的最长时长是 24 小时，可以调高到 72 小时。对希望长期使用同一个 MCP 客户端、但又不希望每次重启主控后重新走浏览器授权的场景，这会造成频繁的人工重新授权。

长期授权模式提供第三种选择：显式、可撤销、可审计的长期授权，而不是放宽所有授权，也不是把 MCP 变成管理员 API Key。

## 启用方式

批准页有「长期授权」选项，默认不勾选。勾选后这条授权在撤销前一直有效；不勾选则仍按所选时长。

授权请求中只有在明确传入 `long_term: true` 时才创建长期授权。字段缺失或为 `null` 时仍按 `duration_minutes` 创建临时授权，因此旧客户端、脚本和其他调用方不会被自动升级为长期授权。

长期授权的到期时间为 `2100-01-01T00:00:00Z`。

## 凭据与撤销

- Access Token 仍为 5 分钟，并按原逻辑轮换；长期只作用于授权（lease）和 Refresh Token。
- 长期授权不绑定浏览器登录会话：登录会话过期、被删除或正常重启都不会撤销它。
- 仍然会被撤销的情况：管理员在“授权详情”中撤销、`撤销全部`、账号安全变更、CLI 重置密码、关闭“启用 MCP 代理”、关闭“允许远程管理”。
- 已有授权保持临时授权，不会被改成长期授权。
- 已撤销或已到期的授权不会被重启重新激活。空的长期标记也按临时授权处理。
- 只有确认授权人账号已经不存在时，才会在下一次使用时撤销长期授权。查询失败不会撤销。
- 刷新令牌时客户端标识必须和签发时一致，空的标识也会被拒绝。
- MCP 终端校验授权、所有者和已选节点。单次终端跟到授权到期，空闲不会结束这次终端；授权到期或撤销后结束。授权本身在到期前仍然有效，可以再开。

## 管理界面

- 授权列表会展示仍然有效的长期授权，即使它创建已超过 3 天；历史窗口仍用于已结束记录的保留。
- 授权详情与授权接口会返回 `long_term`，便于在界面上区分。

## 实现要点

- `database/models`：`MCPLease.LongTerm`。
- `web/mcp/long_term.go`：批准页选择长期授权时的到期策略。已有授权不迁移。
- `web/mcp/store.go`：重启与登录会话失效时跳过长期授权；清理只去除已结束或过期的令牌；账号安全撤销包含长期授权。
- `web/mcp/oauth.go`：客户端绑定校验先于并发等待；令牌消费与后继签发在同一事务内完成，失败回滚；重复使用会撤销整个令牌家族。
- `web/mcp/admin.go`：授权创建、列表与详情。
- `web/api/remote/mcp_lease_validator.go`：MCP 终端按授权而非浏览器登录会话校验。
- `database/accounts/force_password_reset.go`：应急重置密码与撤销该账号 MCP 授权在同一事务内完成。

## 说明

长期授权仍会因撤销、账号被删除、客户端 ID 不匹配或数据库丢失而失效；它不是永久凭据，也不会绕过任何管理员操作。
